# Theater activation work — 2026-10-16, local only

The reported symptom is a whole-page freeze immediately before a nearby theater starts playing, on desktop and mobile. The original desktop path created a second WebGL renderer at startup, but did not draw its entire foreground scene until the first video became visible. That first draw uploaded geometry/materials/textures and rendered shadows into a separate GPU context. The phone path reused one context but changed global clipping-plane count and disabled shadowing when redrawing avatars, introducing fresh material variants on first activation.

All devices now use the existing depth-preserving aperture path in the main renderer. Desktop antialiasing, pixel ratio and normal/lite lighting remain the same. The main pass retains all ordinary world geometry and depth; only avatars whose bounds intersect a screen are redrawn. Their cached main-pass shadow maps stay enabled without another shadow update. A harmless clipping plane beyond the world is present from the first frame, so video activation changes its value rather than the number of shader planes. The old second renderer and whole-scene foreground pass were removed. Shared-clock seeking, one mounted player, venue/room gating, audio policies, private screenings and immersive video playback are preserved.

Unchanged XR fallback posters also retain their canvas texture across public programme updates; title/direct-source changes and removed/video maps still invalidate the cache.
